# Досягнення без Blaze

Активна версія працює без Cloud Functions. Браузер обчислює автоматичний прогрес із збережених даних користувача; Firestore Rules перевіряють права, каталог, фіксовані бали, вітрину й згоду на участь у рейтингу. Не потрібно підключати білінг. Залишаються стандартні квоти Firestore Spark.

Адміністратор видає й відкликає медалі в адмінці. Ручні нагороди зберігаються окремо від автоматичних; звичайний користувач не може видати собі приховану медаль. Повторна видача не подвоює бали, а відкликання ручної видачі не забирає автоматично отриману медаль. Журнал видачі не можна змінити або видалити з клієнта. Адміністратор не може сам увімкнути чужу участь у рейтингу.

Прогрес оновлюється на сторінці досягнень та після збереження відповідних даних у застосунку. Дні активності рахуються раз на календарний день UTC, починаючи з цієї версії. Для спільних тренувань обидва учасники мають відкрити оновлений застосунок: кожен записує підтвердження власного завершення. Правила перевіряють актуальну сесію при читанні підтвердження, тому видалений результат більше не враховується. Чужі журнали тренувань не відкриваються.

Обмеження: автоматичні факти обчислює клієнт. Правила перевіряють відповідність медалей фактам і фіксовану суму балів, але не перераховують усю історію тренувань. Це рейтинг даних, заявлених користувачами, а не незалежна перевірка спортивних результатів. Адміністративні нагороди та доступ до чужих даних захищені правилами.

## Публікація

```powershell
npm run build:achievements
npm run prepare:achievement-rules
firebase deploy --project nexus-gymb --only "firestore:rules,firestore:indexes"
```

Сайт публікується звичайним workflow GitHub Pages. `firestore.rules` залишається локальним згідно з `.gitignore`; генератор змінює лише блок досягнень у наявній копії правил. Код у `functions/` збережено як попередню реалізацію; він не використовується сайтом і не включений у Firebase deployment configuration.

## Перевірка

```powershell
npm test
npm run test:achievement-rules
```

Для браузерної перевірки разом із Firestore Emulator встанови `QA_BROWSER_PATH` у шлях до Chrome. Перевірка використовує справжні клієнтські операції Firestore, тестові акаунти й емулятор; до робочої бази тестові дані не записуються.
